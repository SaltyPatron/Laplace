## Corrections established after this sequence

### The forward program now includes query-relative coupling

The old sequence contained the pre-coupling program:

```text
RESOLVE → ORIENT → ROUTE → ...
```

That is superseded.

The current canonical semantic program is:

```text
RESOLVE → COUPLE → ORIENT → ROUTE → SCAN → COMPOSE
        → PROPOSE → STEER → SELECT → REALIZE → WITNESS
```

The whole admitted observation/root and discourse/obligation state first perturb eligible indexed planes; typed responses participate in joint interpretation before unconstrained policy/provider routing is frozen.

### Execution grain is universal

The August campaign focused heavily on SQL/read-path remediation. The current law applies the same physical rule to every high-volume pipeline:

```text
boundary/orchestrator
-> indexed or set-sized handoff
-> native C/C++ repeated algorithmic work
-> bulk/set result + receipt
```

This includes decomposition, ingestion, cognition, analysis/domain engines, reconstruction, synthesis and export.

### Geometry/carrier semantics are explicit

Current docs distinguish real physicality `coord`, exact mantissa-packed trajectory carrier and realized child-coordinate curve. Packed trajectory values are not spatial positions.

The current native centroid path and managed/domain Karcher paths are also documented as an implementation divergence rather than being silently described as one coordinate law.
