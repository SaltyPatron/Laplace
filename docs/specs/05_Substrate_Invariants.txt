SUBSTRATE INVARIANTS
====================

This file is normative. Code that violates a rule here is a defect.

Rule #1 — Content identity is exact
-----------------------------------

An entity id is derived only from canonical content through the substrate identity
surface. Callers resolve ids with canonical helpers; they do not manufacture hashes.
Two observations of identical content converge on one entity id regardless of source,
modality, ingestion order, or interpretation.

A codepoint's id is BLAKE3 of its UTF-8 bytes, read from the Tier-0 ROM. A
composition's id is BLAKE3 over its children's 16-byte ids, in order, repeats
included, truncated to 16 bytes; a one-child composition is that child. The hash input
holds nothing else: no domain byte, tier, type, recipe name, version, source, position,
index, or role label. A recipe decides how content decomposes into a tree; it never
salts a hash.

Identity is one Merkle DAG from leaf to trunk: the recipe's tiers compose to a file's
content tree; a file is `[metadata, content]`; a source is `[source record, its files'
trunks in path order]`. A release is its files, so a new release has a new source
trunk. Any client computes any id from the ROM with no database.

Hashes are never faked. A hash of a made-up string (`substrate/source/X/v1`,
`language:eng`, `operation/what_is/v1`) is a fake identifier, and a blob hash of a
string's raw bytes gives the same text a second id. Such a string is decomposed
content, a referenced trunk, or a recorded attestation.

A source's identifiers are of two kinds. A hub (an ILI, a PropBank roleset, a VerbNet
class, a FrameNet frame, frame element or lexical unit, a VerbAtlas frame, a language
code) is content: `i46360` is `[i,4,6,3,6,0]` wherever that text occurs, every source
that cites it lands on the same entity, and that it is an ILI is attested by the source
that says so. An internal pointer (a WordNet synset offset, a synset or sense id, a
FrameNet numeric id, a UD token number or `sent_id`, a Tatoeba number, a geonameid, a
row or line number) is how a source addresses its own records. The recipe decomposes it
by the source's own notation only for the facts it carries (a WordNet offset's type, a
sense key's lexicographer file), resolves it through the source's tree or the highway
perfcache to the id of what it points at, and records nothing of it. Whether a sense
key is such a pointer or a lexicalization in its own right is open. A WordNet offset
is a byte position in one release's `data.<pos>` file, unique only with its type, and
19,619 of WordNet 3.0's 117,659 synsets share their exact word list with another, so a
synset is its ILI hub, neither its offset nor its words. A record's position in a file,
a line number, or a byte offset is occurrence under the trunk, never part of an id.

Coordinate equality, spatial proximity, a shared name, or an ordinal slot is evidence
about entities. None replaces content identity.

Rule #1b — Tier is altitude, not identity
-----------------------------------------

Tier is a property of a representation level and is never an input to the content hash.
The same content has the same id at every tier. Tier predicates cannot be used as a
proxy for semantic role, source, or modality.

Tier 0 is the universal Unicode codepoint floor for all content: every modality
decomposes to codepoint leaves. A raw byte, sample, or channel value is a number, a
composition of digit codepoints under the scalar recipe, never a leaf of its own. Tokens, words,
phrases, sentences, documents, programs, games, model circuits, and other modalities
compose above that floor; packaging bytes do not redefine their content identity.

Rule #1c — Finite scalars are compositions, not new atoms
-------------------------------------------------------------

An arbitrary finite digital scalar does not mint a new Tier-0 atom merely because it
appears in a physical modality.

Under its declared exact numeric recipe, the scalar is canonical ordered content over
the existing codepoint floor. For example:

    255     -> ['2','5','5']
    0.34567 -> ['0','.','3','4','5','6','7']

Those constituents compose into one reusable scalar root. Re-observing the same exact
scalar reuses that content id; sample/channel/pixel/tensor/time/ordinal/source context
is occurrence/physicality state around it.

A finite prefix of pi obeys the same rule at larger width. It is one ordered
composition over existing digit/punctuation atoms, not one new atom kind per digit or
one new Tier-0 atom per numeric value. Local packed ordinal/run field widths are
serialization fields, not global composition-width limits.

Analog phenomena enter only through a finite digital observation. The scalar recipe
must retain enough radix/sign/precision/scale/exponent/source-format information to
reconstruct that admitted digital value. An incidental host floating-point rendering
is not authority when it loses source precision.

Content novelty and occurrence volume remain distinct.

Rule #1d — A constituent composition is one entity everywhere
------------------------------------------------------------

Canonical identity is the ordered canonical constituent identity sequence.

If:

    ['k','i','n','g']

composes to entity K, then K is the entity referenced everywhere that exact composition
occurs. "word", "name", "title", "label", "token", source, sentence position, language
use, tier, container, sense, or task role do not mint another K.

Those facts live in physicality/trajectory, occurrence, typed relations, testimony,
context or calculation around K.

The same rule applies recursively to image structure. If an exact ordered 2x2 pixel
composition P occurs inside an 8x8 region, inside another image, or as a standalone
selected patch, every occurrence references P. The containing 8x8 does not own a
private copy or tier-specific hash of P.

Likewise, if the exact ordered constituent sequence is admitted at two different tiers,
hash128_merkle produces the same id. Tier is deliberately discarded by the executable
hash law.

Do not salt content identity with a domain byte, tier, recipe, version, source,
parent/container, occurrence ordinal, semantic role/type label, modality, cache
profile, physicality or provenance when those
facts do not change the canonical ordered constituent content itself.

Rule #2 — Physicality is typed
------------------------------

`coord`, `hilbert_index`, `trajectory`, and realized curves are different facts:

- `coord` is a point placement on S³.
- `hilbert_index` is a locality/serialization key derived from placement.
- `trajectory` is the lossless ordered constituent manifest.
- a realized curve is the ordered sequence of constituent coordinates.

Code must select the representation required by the operation. A point cannot answer
an order question; a packed trajectory cannot be passed to a geometric distance
operator as if its mantissas were spatial coordinates.

Rule #3 — Order lives in trajectories
-------------------------------------

Composition above tier 0 does not preserve coordinate equality. Order-sensitive facts
use trajectory ordinals. Corpus adjacency is inferred from physical composition and
containment; it is not duplicated as unconditional ordinary `PRECEDES` testimony.

Exact occurrence is an indexed containment question. Resolving one entity point and
asking which trajectories contain it must recover every attested occurrence without
text scanning or approximate-nearest-neighbor substitution.

Rule #4 — Packed geometry is a serialization contract
-----------------------------------------------------

Mantissa-packed `GeometryZM` values carry ids, ordinals, flags, scores, counts, and
other typed payload. Those values require the matching pack/unpack implementation.
Their storage type does not make them geometric paths. Every producer and consumer
must agree on version, vertex class, field layout, and bounds.

Rule #5 — Evidence retains provenance
-------------------------------------

An attestation is a witness asserting one claim. The claim is an n-ary composition
of content ids with referential integrity, of any arity and any tier (a lexicalization
`[lemma, language, ILI]`, a concept relation `[ILI, hypernym, ILI]`, a role inside a
roleset, a valence pattern); `(subject, relation, object)` is one claim shape among
many. The witness is the source trunk, `[source record, its files' trunks in path
order]`. Provenance is containment: a source's record is a path over the claims it
asserts, inside its file's content tree, with each claim's run length, outcome and
score in its vertex; many source trunks can contain the same claim, and a walk up from
the claim finds them all. Trust and lineage are keyed by the trunk id. Forgetting a
source removes its trunk, sweeps what nothing references, and replays the standings it
touched. Absence is unknown, not refutation.

The current schema keeps a per-(claim, witness) `attestation` row whose witness is
`SourceWitness.Id(authority, release)`. That is not the source trunk; containment
replaces the row, and nothing new is implemented from it.

A witness asserting the same claim n times plays n games, run-length. The client folds
every repeat from one source, per cell, into one Glicko-2 rating period, and the
database receives one update per cell per witness; different witnesses play first in,
first out. The run length is also kept as a count beside the claim. A number the source states (a usage count, a sense order) is an
observation, not games. A derived witness records its lineage, so copies count once. Refutation, draw, and confirmation remain distinct outcomes.

Observed testimony is append-only evidence. Corrections add new testimony; they do not
erase the earlier witness. Calculated testimony identifies its analyzer and version.

Rule #6 — Consensus is one typed cell
-------------------------------------

The consensus address is the claim composition. Every source speaking about that
claim folds into the same standing cell while the record paths that assert it remain
inspectable. Standing (rating, deviation, volatility, matches) is one table keyed by
the claim id, beside the path, never on the GIN-indexed path row.
The cell is never keyed by `BLAKE3(subject || type || object)` with a zero-filled
missing object. Rating, deviation, volatility, witness count, and
source/context scope are part of the decision surface.

Consensus is not an answer vote. It is the standing evidence state consumed before and
during one forward pass.

Rule #7 — Relation types are governed
-------------------------------------

Relations are content-derived entities whose meaning is attested and realizable in any
language. `engine/manifest/relation_types.toml` governs the relation registry, a
perfcache over those entities: its highway bits are explicit, append-only slots, never
relation identity, and its English names are developer handles. Aliases are attested
equivalences: a source's own code is recorded as it arrives and sets the same bit as
the relation it means; aliases do not mint parallel meanings. No code path tests for
an English value. Salience band, rank, hotness, and highway membership are separate
properties.

Rule #8 — Determinism and receipts are product properties
---------------------------------------------------------

Given the same canonical content, declared source scope, seed profile, operation
program, and deterministic configuration, Laplace must produce the same identities,
fold state, selected result, and provenance receipt. A cache, export, or alternate API
surface may not silently change semantic execution.
