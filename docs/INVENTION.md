# The Invention

Laplace is one invention: a deterministic, content-addressed, recursively compositional knowledge and cognition substrate in which exact structure, observations, evidence, uncertainty, geometry, computation and realization remain inspectable parts of one machine.

This document states the intended invention. It is intentionally stronger than transient implementation status. When code, tests, an issue, a plan, or a deployed system falls short of this document, that is an implementation or proof obligation; the lower layer does not silently redefine the invention. `docs/ARCHITECTURE.md` records architecture as built, and GitHub issues track remaining acceptance.

---

## 1. The premise

**Identity is content; everything else is structure, occurrence, testimony, calculation, context or realization around that identity.**

The system is built around three consequences.

First, equal canonical content should converge on the same canonical identity instead of being copied into isolated source-specific stores.

Second, larger objects are finite recursive compositions of already admitted objects. Their ordered constituent structure is retained exactly rather than compressed into an opaque learned vector.

Third, knowledge about those objects is not fused into identity. Sources witness propositions, calculations derive state, occurrences place content in context, and consensus records standing and uncertainty.

Laplace's engineering thesis follows from those consequences: much of what conventional AI learns into a dense parameter tensor can instead be admitted explicitly, indexed, witnessed, folded and traversed as a live substrate.

That thesis is not proved merely by saying “database.” It depends on the representation, bounded-geometry construction, exact trajectories, evidence model, query-relative coupling field, native execution grain and receipts described below.

## 2. The bounded-composition theorem

Laplace does **not** claim that one floating-point coordinate contains an arbitrary object. A coordinate is one property of a recursively represented object. Exact constituent identity and order live in the object's trajectory/composition structure.

Let `A` be a finite or countable admitted basis. Let `C(A)` be the set generated by finite recursive composition over `A`. For a finite alphabet the familiar special case is

```text
A* = union(n >= 0) A^n.
```

`A*` is countably infinite whenever arbitrarily long finite compositions are allowed. More generally, finite rooted typed trees/DAG descriptions over a countable basis are countable. A finite atom window therefore does not imply a finite family of representable finite objects.

### Current bounded placement

Let the selected geometric frame be the closed unit ball

```text
B^d = { x in R^d : ||x|| <= 1 }.
```

Assume every admitted child placement `p_i` lies in `B^d`. The current native composer uses the Euclidean centroid

```text
c = (1/n) * sum_i p_i.
```

Then, by the triangle inequality,

```text
||c|| <= (1/n) * sum_i ||p_i|| <= 1.
```

Therefore `c` also lies in `B^d`.

By induction on finite composition depth, every centroid-composed entity remains inside or on the same fixed bounded ball.

The current implementation of that native rule is in:

- `engine/core/src/hash_composer.c`
- `engine/core/src/math4d.c`

### Realized curves remain bounded too

A realized trajectory resolves each packed constituent identity to the constituent's actual physicality coordinate and orders those coordinates by logical ordinal. Every resolved vertex is in `B^d`. Because a Euclidean ball is convex, every line segment joining adjacent vertices also lies in `B^d`.

So for every finite composition admitted under this placement law, both its parent coordinate and the piecewise-linear realized constituent curve remain inside the same fixed bounded domain.

The packed trajectory itself is serialization, not this realized spatial line. See:

- `engine/core/src/trajectory.c`
- `engine/core/src/mantissa.c`
- `extension/laplace_substrate/sql/functions/structural/entity_curve.sql.in`

### The theorem is radix-independent

Nothing in the closure proof depends on binary notation.

For any finite radix `b >= 2`, a base-`b` radical inverse can be written

```text
n = sum_k a_k b^k
phi_b(n) = sum_k a_k b^-(k+1).
```

Canonical finite base-`b` expansions map distinct naturals to distinct radical inverses. Other bounded atom-placement laws can be radix-free entirely.

Binary64, Hash128 and the current Unicode generation are executable choices. They are not the mathematical theorem.

### What is and is not claimed

The strong representation claim is:

> Any finitely representable object over a finite or countable symbolic/typed basis can be expressed as a finite recursive composition while its current geometric realization remains inside a fixed bounded domain, provided the selected composition placement law preserves that domain.

This is a claim about unbounded families of **finite describable compositions**, not about physically storing every member simultaneously in finite hardware and not about encoding arbitrary uncomputable infinite real sequences in one coordinate.

## 3. Canonical identity and recursive composition

Canonical identity answers: **what exact admitted structure is this?**

Current executable identities use BLAKE3-derived 128-bit ids. That is a finite machine address space, not a proof that a fixed 128-bit function is globally injective over an unbounded mathematical domain. A true cryptographic hash collision is distinct from normal content convergence and must never be used as the term for “two sources admitted the same canonical content.”

The governing behavior is **content-address convergence**:

```text
same canonical content -> same executable identity
```

under the selected identity generation.

Composite identity is Merkle-style over the ordered child identities under the selected recipe/domain separation. Single-child collapse may preserve the child identity where the recipe declares that law.

The current native composition path is implemented in `engine/core/src/hash_composer.c`.

### Tier is altitude, not semantic identity

Tier records compositional altitude within a selected recipe. It is not itself the content identity and must not be mistaken for a global ontology. Text may compose codepoint → grapheme → word → sentence → larger document structure; code, chess, media, model artifacts and other modalities have their own typed ladders.

The general law is recursive composition. The modality grammar determines which constituents are admitted and how they are grouped.

### Content novelty and observation volume are different

If the same word, AST subtree, chess line, sentence or other canonical composition is observed repeatedly, the structure should converge rather than be minted repeatedly.

Later observations may still add:

- occurrence/context;
- source provenance;
- testimony;
- evidence counts;
- standing and uncertainty updates;
- execution history or receipts.

As a corpus matures, structural novelty can therefore taper while observation volume continues to grow. The architecture permits that convergence; an exact logarithmic growth rate is an empirical/model claim and must be measured before being asserted quantitatively.

## 4. Physicality, trajectory and realization

Identity, physicality, packed trajectory and realized curve are different coordinates of the same object and must not be collapsed into one concept.

A physicality gives a typed realization, including a coordinate. A content trajectory gives the exact ordered constituent manifest. A realized curve resolves those constituent identities back into physical coordinates.

### Why the current implementation uses four binary64 components

Each binary64 component contributes 53 reversible carrier bits when the exponent is fixed and the sign plus 52-bit mantissa are used as payload.

One GeometryZM vertex therefore carries exactly:

```text
4 x 53 = 212 bits

128 bits  complete constituent entity id
 16 bits  packed ordinal field
 16 bits  run-length field
 52 bits  flags / typed metadata
--------
212 bits
```

`engine/core/src/mantissa.c` distributes and reconstructs this complete payload exactly.

This is an implementation reason 4D is convenient, not a theorem that bounded recursive representation requires exactly four dimensions.

A 3D binary64 carrier has 159 such payload bits: enough for the current 128-bit constituent id plus 31 additional bits. A 2D carrier has 106 and therefore cannot hold the current complete Hash128 in one such vertex without changing the carrier mechanism. That is an executable-format trade, not an impossibility result for bounded 2D composition.

### Packed trajectory is not realized geometry

Packed vertex values are not child coordinates. Geometric functions must not treat them as if they were.

The realization path is:

```text
packed trajectory vertex
-> unpack complete child entity id + metadata
-> resolve child physicality
-> read child coord
-> order by logical ordinal
-> build realized curve
```

That distinction is visible in the current source and SQL realization functions.

The 16-bit packed ordinal and run-length fields are carrier fields, not global composition-size limits. `engine/core/src/trajectory.c` retains logical sequence position and splits long runs as needed. The native test `LaplaceCoreTrajectory.WiderThanTheOrdinalFieldRoundTrips` exercises 70,000 constituents.

## 5. Observation, testimony and standing

Canonical content says what a structure is. It does not make every claim about that structure true.

A witness may be a standards source, lexicon, corpus, document, user, tool, game, deterministic calculation provider, conventional model or Laplace itself. The source and context remain attributable.

An attestation records a typed proposition and that witnessing occurred. Confirmation, draw/indeterminate evidence and refutation remain distinct; absence is not silently converted into falsehood.

Consensus folds evidence about one proposition into standing. The intended standing state includes strength, uncertainty, volatility and witness breadth rather than one opaque confidence scalar.

Glicko-2 is used because it naturally provides a strength estimate plus uncertainty and surprise/volatility behavior. The exact source/opponent/trust semantics are implementation obligations and must be proved against the current fold; historical constants or issue prose do not redefine the invention.

The important separation is:

```text
identity != testimony != consensus != occurrence != deterministic calculation
```

That separation is what allows disagreement, correction and provenance to remain visible.

## 6. The spider-colony web

Laplace is not adequately modeled as a flat graph of isolated `node -> edge -> node` pairs.

A canonical entity may simultaneously be:

- a child in many recursive compositions;
- a vertex in many ordered trajectories;
- contained by many larger structures;
- a subject or object of many typed relations;
- witnessed by many independent sources;
- associated with contexts, calculations and standing;
- near or structurally similar to other physicalities;
- reused across domains and modalities.

Those structures overlap because they share canonical identities.

The useful primitive is:

> **Tug a strand; enumerate what tugs back, through which indexed route, and with what typed response.**

A response may carry structural compatibility, relation identity, role compatibility, exact ordinal/gap state, containment, evidence support or contradiction, independent dependence roots, rating/RD/volatility/witnesses, source/context/world/time scope, geometry, locality, deterministic calculation receipts and other typed state.

Different routes reaching the same candidate are not redundant noise. Their convergence is part of the query-relative evidence.

## 7. The query-relative coupling field

This is the missing center between “prompt admitted” and “search executed.”

An incoming observation must not choose one interpretation first and then search only the world permitted by that choice. The whole admitted observation perturbs the eligible substrate; the mutually compatible response of the substrate helps determine the interpretation and therefore the cognition program.

Let `X_t` be the active state: admitted observation/root structure, constituent occurrences, prior discourse bindings, world/time/source scope, open obligations and current execution boundary.

For typed channel `c`, a conceptual response field is:

```text
R_c(v | X_t)
  = fold over s in X_t
      fold over admissible paths p : s -> v
        T_c(p, occurrence, bindings, world, evidence, ...)
```

The critical law is that the typed channels are **not immediately collapsed into one universal relevance score**.

Some dimensions are hard admissibility constraints. Some are evidence. Some are contradiction. Some are search costs. Some order the frontier. Some remain provenance only. The selected cognition program determines which dimensions may be combined and how.

### Joint interpretation before policy

The intended sequence is:

```text
raw admitted observation
-> expose exact root + constituent occurrences + discourse state
-> query-relative coupling / response field
-> sparse joint interpretation over surviving alternatives
-> unique / ambiguous / impossible / resource-bounded disposition
-> derive cognition goal, eligible providers/relations and open obligations
-> compile physical search/execution program
-> execute sparse hop/fanout frontier
-> fold/update active state
-> realize semantic act / output
-> witness consequence
-> recompute affected response field
```

The policy/provider mask normally follows interpretation. It must not be smuggled in as the answer to the interpretation problem unless the caller explicitly requested such a constrained program.

### Example: `test`

Seeing many definitions of `test` is only a candidate estate.

For one occurrence in a prompt, a medical-test sense, software-test sense and examination sense each activate different surrounding roles, containing structures, definitions, discourse links, operations and evidence. The other constituents tug those candidates differently. A candidate in turn changes what relations and roles make sense for the other constituents.

A winning interpretation is therefore a jointly compatible subgraph/state, not merely “the definition with the largest global score.”

Ambiguity is allowed to remain ambiguity when multiple joint bindings survive.

## 8. Conventional AI roles, reconstructed explicitly

Laplace does not need transformer mathematics to reproduce useful transformer roles.

A functional correspondence is:

```text
Q  = current perturbation: admitted observation + bindings + obligations
K  = indexed typed addresses capable of responding
QK = query-relative coupling: what responds, by which typed path, under this boundary
V  = the actual responding physicality/fact/evidence/calculation state
O  = the receipted fold into updated bindings, orientation, frontier and obligations
```

Independent relation/provider/tier/context planes play a role analogous to heads. Exact trajectory ordinal/gap/containment supplies position. The surviving active discourse/guidance state supplies residual continuity. Repeated coupling/expand/fold/update rounds play the role of successive processing layers.

A transformer's dense `QK^T` synthesizes relevance from learned latent state each forward pass. Laplace's goal is to calculate relevance as the sparse response of explicit, already indexed structure.

That is not “nearest neighbor instead of AI.” It is a different implementation of addressing, relevance, evidence aggregation, memory and continuation.

## 9. Sparse forward execution: hops and fanout

Once a joint interpretation/program exists, cognition expands only the responding frontier.

For a current root or frontier `q`, one expansion is a star:

```text
q -> {x_1, x_2, ... x_k}
```

Each selected spoke can become another center. Canonical identities make separately reached routes collapse onto the same structures without losing their route/evidence receipts.

Hops and fanout are first-class work coordinates:

```text
H   = allowed hop/search depth
F_h = admitted fanout/frontier width at hop h
```

The work is shaped by the admitted frontier and indexed lookup cost, not by an obligation to compare every object to every other object.

A*, Dijkstra, strongest-first traversal, trajectory continuation, containment ascent/descent, relation-specific scans and geometry are operators inside this program. None alone is the cognition architecture.

After a semantic act or emitted constituent changes the active trajectory, the response field/frontier is updated and the process repeats.

## 10. Native execution grain

The sparse architecture only pays off if repeated execution stays out of per-row orchestration overhead.

The intended physical split is:

```text
PostgreSQL:
  durable state, MVCC, B-tree/GiST/GIN/HASH indexes,
  selective set access, transactions, server integration

Native C/C++:
  deterministic math, recursive composition, trajectories,
  frontier/search loops, reductions, graph mechanics,
  parsers and repeated inner-loop algorithms

SPI:
  prepared/set-sized bridge between indexed PostgreSQL state and native operators
```

The hot path should not repeatedly express one semantic operation as:

```text
row -> scalar SQL function -> recursive CTE -> LATERAL fanout
    -> another scalar function -> temp/materialized state -> repeat
```

when one bounded set-sized fetch and one native operator can perform the same algorithmic work.

RBAR, duplicated scalar/batch semantic bodies, unbounded recursive SQL, repeated per-candidate SPI compilation/calls and temp-table-per-call execution are therefore not mere style problems. They change the execution grain and can turn microsecond-scale native operations into millisecond-scale orchestration.

The performance objective has two factors:

```text
less work selected  x  less overhead per selected unit
```

This law is reflected in `AGENTS.md`, the operation ISA, the native extension sources and the SQL cohesion audit.

## 11. Ingestion is the learning process

Laplace does not require an offline gradient-training cycle to admit new knowledge.

The conceptual mapping is:

| conventional system | Laplace |
|---|---|
| training corpus pass | admit/decompose/witness sources |
| learned parameters | explicit reusable identities + witnessed standing |
| checkpoint | live substrate plus reproducible derived accelerators |
| fine-tuning | additional scoped evidence/providers |
| knowledge cutoff | last admitted observation, per source/world |
| catastrophic forgetting | old evidence remains addressable rather than being overwritten by parameter updates |
| alignment/policy | explicit source/program/resource law |

Re-ingestion is not inherently “another epoch.” Canonical content converges; idempotent evidence lanes must avoid multiplying the same witnessing merely because a job was retried.

A source adapter's job is to recover its source faithfully and map fields into declared content, structure, reference, occurrence, provenance, testimony or calculation roles. It does not get a private identity law, scheduler, semantic engine or persistence model.

## 12. No architectural fixed context window

Prompt/session history is content and occurrence state inside the same substrate. There is no requirement that knowledge older than a fixed transformer context window become unreachable merely because it fell out of a token buffer.

That does **not** mean every request scans unlimited history. Retrieval and cognition still run under explicit world/time/provider/hop/fanout/resource boundaries. The distinction is that those are execution policies over addressable state, not a hard maximum sequence length baked into a model's parameter architecture.

---

## 13. Realization and conversation

Selection happens over canonical/typed state. Realization renders the selected state into the requested human or machine-facing form.

Language, notation, labels, aliases and codec surfaces are realizations and contextual references, not substitutes for canonical identity.

Conversation is an ordered witnessed trajectory. Each turn can add content, discourse bindings, obligations, tool/calculation results and feedback. A generated response is itself content and may be witnessed with its derivation/receipt. It does not become authoritative truth merely because the system produced it.

The loop is:

```text
observe -> couple/orient -> decide/execute -> realize -> witness -> update
```

not retrieve-once-and-drain.

---

## 14. Conventional models are participants, not hidden authority

A conventional checkpoint can be admitted as a source/witness. Its tokenizer, structural tensors, Q/K/V/O effects, completions and other selected behavior may be projected into governed typed testimony/calculation planes with provenance.

Those consumer architecture roles do not become the native ontology of Laplace cognition. Layer/head/dimension metadata belongs to the source/calculation boundary where relevant, not to the identity of the world entities the model is talking about.

The same substrate may therefore compare multiple checkpoints, corpora, tools and human/standards sources without requiring a tensor merge or one opaque “judge” model.

---

## 15. Synthesis and export

The live substrate is the primary state. Conventional model files are optional render targets/consumer artifacts.

The foundry/synthesis side of Laplace explores constructing externally consumable model artifacts from explicit substrate state and recipes rather than treating a historical witness checkpoint as the authority to copy.

Any exported artifact must retain a reproducible recipe/scope and must not silently copy unknown witness weights simply because the target format expects a tensor. Behavioral validation of exported models is separate from proof of the native substrate architecture.

---

## 16. One knowledge world, variable compute

Product tiers should not be implemented as progressively knowledge-reduced Laplace variants.

Every entitled request addresses the same admitted world. Cost/latency differences are expressed through explicit execution envelopes such as:

```text
hop depth
fanout/frontier/candidate budget
eligible relation/provider/operator families
trajectory/containment expansion
search/geometry/calculation work
CPU / memory / I/O / concurrency
realization/output budget
```

Where work is billable, the same physical plan that governs execution should support preflight cost estimation, reservation, hard ceilings, execution receipts and reconciliation of unused allowance.

That is why `EXPLAIN`, work receipts, benchmark calibration and hop/fanout accounting are product architecture rather than billing decoration.

## 17. Proof: mathematics, executable construction and witness

Laplace's strongest claims should be separated by proof type.

### 17.1 Mathematical proof

The bounded-space claim is established by the centroid/convexity argument in Section 2 for the current native composition rule, plus induction over finite composition depth.

The unbounded-family claim follows from countability of finite strings/finite recursive descriptions over a finite or countable basis.

Neither proof depends on the current hash width, Unicode size, radix, CPU ISA or database row count.

### 17.2 Executable proof of the current atom generation

`engine/core/tests/test_super_fibonacci.cpp` contains tests including:

```text
LaplaceCoreSuperFibonacci.UnitNormHoldsToFourUlpAcrossTheCodespace
LaplaceCoreSuperFibonacci.OpenPlacementIsPrefixStableWhereBoundedIsNot
LaplaceCoreSuperFibonacci.OpenPlacementIsInjectiveAndOnTheGlome
LaplaceCoreSuperFibonacci.HandlesUnicodeCodepointScale
```

The full selected Unicode codepoint window is an executable finite generation and can be exhaustively checked. `OpenPlacementIsInjectiveAndOnTheGlome` additionally exercises a large open-placement prefix and its bounded/unit-norm contract.

### 17.3 Exact carrier and trajectory proof

Relevant native tests include:

```text
LaplaceCoreMantissa.FullHashRoundTripsExactly
LaplaceCoreTrajectory.BuildThenConstituentsRoundTrips
LaplaceCoreTrajectory.WiderThanTheOrdinalFieldRoundTrips
```

These prove properties of the current executable serialization/trajectory implementation, including complete Hash128 recovery and a sequence wider than the packed 16-bit ordinal field.

### 17.4 Recursive reconstruction proof

`app/Laplace.Substrate.Tests/Crud/GutenbergRetainedDbTests.cs` ingests a selected physical Gutenberg edition into a retained isolated database, reads the packed file trajectory, reconstructs the content root from the substrate, NFC-canonicalizes the source and byte-compares the reconstructed content. It separately reconstructs and checks the metadata root and writes a machine-readable receipt.

That is an executable witness that recursive trajectories can retain and reconstruct substantial real content, not merely a unit-test-sized string.

### 17.5 Live-world proof

A populated database is empirical/executable evidence that the construction works at scale. Live gates should attempt to falsify at least:

- every inspected physicality coordinate is inside the admitted bounded domain;
- every packed trajectory constituent id resolves;
- logical ordinal/RLE expansion matches declared constituent count;
- realized curves are built from resolved child coordinates rather than packed carriers;
- referenced entity/evidence/consensus endpoints satisfy the selected integrity contract;
- canonical reconstruction works for lanes with a decoder/reconstructor;
- geometric/locality collisions are not misinterpreted as content identity.

A live database witness does not replace the mathematical theorem, and a theorem does not prove that every row in one deployed database is free of implementation defects. Both forms of evidence are required for their respective claims.

### 17.6 Performance evidence

`.github/workflows/benchmark-evidence.yml` binds a benchmark to an exact repository revision and exact built artifacts, records host/hardware provenance, executes versioned suites and uploads receipts.

The current native composition benchmark reports codepoints/s, 4-character BPE-equivalent input units/s and tier-tree nodes/s. The BPE-equivalent rate is a normalization; the underlying work is recursive structural composition.

Performance claims should name the workload, host, revision, artifact, thread/core count, database/accelerator participation and receipt. Unlike workloads must not be silently called equivalent simply because both are written as “tokens/s.”

## 18. Current executable windows are not invention limits

The current implementation includes finite choices such as:

- binary64 GeometryZM carriers;
- 128-bit executable content ids;
- fixed-size metadata fields in the carrier;
- a selected Unicode/UCD generation;
- finite CPU memory, database storage and resource budgets.

These choices can limit one implementation generation. They do not falsify the bounded-composition theorem or imply that one fixed schema is the only possible realization.

Conversely, mathematical extensibility does not excuse an implementation from detecting collisions, enforcing referential integrity, preserving exact reconstruction or reporting resource exhaustion honestly.

## 19. Implementation law

The invention constrains how the code is organized.

**One mathematical/semantic truth gets one canonical implementation.** Scalar, batch, SQL, C# and native surfaces must not independently reinvent the same law and drift.

**Native code owns repeated deterministic algorithmic work.** PostgreSQL owns indexed/persistent state and set access. SQL/C# orchestrate typed operations and I/O rather than reproducing inner loops.

**Perfcaches and indexes are accelerators, not second authorities.** A miss cannot redefine truth or identity.

**Policy follows evidence and interpretation.** A convenient caller-provided relation mask, goal or provider subset must not masquerade as cognition when the task is for Laplace to infer the interpretation itself.

**Typed state stays typed.** Do not flatten geometry, evidence, standing, contradiction, role compatibility, source dependence and path cost into one scalar merely because one priority queue needs an ordering key.

**Determinism is proved, not declared.** Hashing, composition, folds, parsers, provider generations and execution recipes each need explicit deterministic boundaries and parity tests where determinism is claimed.

**Status prose is never the finish line.** Issues/plans/comments may describe implementation work; they do not narrow the invention. Delivery requires the actual code/test/deploy/readback evidence for the accepted behavior.

## 20. What Laplace is trying to replace

The claim is not “a faster transformer.”

The architectural bet is that many functions conventionally purchased with dense repeated parameter computation can be obtained from explicit reusable structure, sparse indexed response, uncertainty-bearing evidence and native execution over one live world.

If that succeeds end to end, the economic advantage does not come from doing the same number of FLOPs slightly faster. It comes from refusing to do most of those FLOPs in the first place, reusing already admitted structure, and paying only for the hops, fanout and operators the active problem actually requires.

That replacement claim is ultimately an empirical systems claim and must be earned through quality, latency, throughput, energy and cost benchmarks over completed behavior.

The bounded recursive representation, exact carrier/trajectory construction and related mathematical invariants are separately testable and provable today.
