# Documentation archive

Everything under `docs/archive/` is **historical evidence, not current repository authority**.

This directory intentionally preserves dated reports, superseded specifications, agent-generated plans/prompts, status snapshots, measurements, rejected designs and prior invention wording so chronology and counterexamples are not lost.

An archived statement may be useful for understanding why a test/issue exists. It may not override current inventor instruction, `docs/INVENTION.md`, `docs/INVENTIONS.md`, binding current specs, `AGENTS.md`, current decisions/plans or current code/test/live evidence.

In particular, do not revive from the archive merely because it is more detailed:

- an MVP/shortcut/fallback as the intended architecture;
- an old fixed work ordering or completion percentage;
- a historical finite machine limit as a mathematical limit;
- packed trajectory values as realized coordinates;
- “walk/search = cognition” without the current coupling/orientation program;
- old claims that a separate repository owns the meaning of the invention;
- historical benchmark/DB/runtime numbers as current evidence;
- an obsolete forward-path gap that current source has already repaired.

When an archived artifact conflicts with current authority, keep the archive intact and correct the current-facing source that is still citing/relying on it.

Archive families:

- `specs-v1/` — complete pre-governance annotated specification set;
- `status/` — dated checkpoints and backlog snapshots;
- `plans/` — annotated completion/workstream plans and audits;
- `reports/` — dated operational and consolidation reports;
- `catalogs/` — superseded annotated catalogs;
- `invention/` — superseded invention experiments and campaign trackers;
- `guides/` — measured guide snapshots containing then-live counts/gaps;
- `agent-plans/` — superseded harness-generated plans;
- `agent-prompts/` — superseded pasteable prompts.
