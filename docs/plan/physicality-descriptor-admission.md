# Immutable physicality descriptors in the Original substrate

Status: implementation obligation. The native identity, staged-body capture,
copied vocabulary, finite geometry materializer and typed readback owners below
are implemented. The normal Npgsql/consensus writer is connected to the bounded
PostgreSQL materializer and its ordinary generated stages. Host ingestion,
deposition and indexed product readback still require executable acceptance.
This checkpoint does not establish delivery of physicalities as ordinary
entities in a running substrate.

## Identity and retained evidence

The existing `laplace_physicality_id_compute(E, type)` and managed twin remain
byte-compatible. They address the current typed placement of E. Several exact
bodies can occur at that address; the address cannot identify each immutable
body. For example, `conversation_session.c` updates a session projection's
manifest under one stable session/type address. An overwritten body cannot be
reconstructed unless it was actually retained.

`physicality_descriptor_plan_build` describes each supplied body as ordinary
native ordered composition. It preserves E as an ordinary entity operand and
does not change E's identity. The descriptor root has nine ordered fields:

1. Canonical schema constituent.
2. Realized entity E.
3. Physicality type as a typed exact 16-bit word.
4. Coordinate tuple with four exact binary64 words.
5. All sixteen stored Hilbert bytes.
6. Exact stored trajectory carriers, in order, or explicit absence.
7. Declared constituent count as a typed exact 32-bit word.
8. Absent or present alignment residual, preserving exact binary64 bits.
9. Absent or present source dimension.

Typed word bytes are references to the existing canonical decimal number
entities 0 through 255. They are not a new atom alphabet. Schema and field tags
are supplied canonical vocabulary entities. The native boundary rejects any
alias between vocabulary entries before encoding or decoding. The production
provider derives and retains the actual vocabulary through the Original
content/number owner, with its verified floor checksum and source receipt; the controlled test
provider is not a substitute for that integration.

An ordinary or testimony carrier contains its actual child E as an ordinary
operand, plus its exact stored ordinal, run and flags. Factor carriers retain
their exact numeric words: their id-sized payload is not an entity reference.
Logical count validation uses the existing trajectory owner, including runs
beyond the packed ordinal window for ordinary manifests. The shared native
`laplace_physicality_manifest_validate` classifies carriers before applying
that law: testimony's run channel means games, and a factor's corresponding
bits contain its fifth binary32 value. Non-Content typed payloads retain their
type-owned constituent count; these fields are not expanded as RLE. Ordinary
non-Content still validates its count, and Content still validates its unchanged
canonical identity. Distinct exact forms get distinct descriptor
content while identical forms reuse the same content. Recording an observed
form does not certify a divergent geometric calculation as correct.

Observation time and source are separate from immutable body identity.
`physicality_descriptor_capture_stages` reads real native IntentStage COPY
tuples before placement dedup, retains every body and occurrence, checks the
placement address, and owns decoded trajectory storage. It exposes the source
stage/row and observation timestamp so orchestration can attach the actual
source/replay receipt. The native physicality tuple itself does not contain a
source id; none is inferred or fabricated.

The ordered-composition producer preserves every computed multi-component
physicality before entity/witness dedup can discard its form. It emits the
existing minimum-floor placement winners first, then remaining raw candidates;
entity rows retain their previous dedup behavior. Each request returns the
actual starting physicality-row offset and appended row count, so a mixed-source
bulk call can retain source provenance without guessing which requests deduped.
Offsets can be out of request order. Singletons create no wrapper entity or
self composition. Repeated exact observations retain the same descriptor
identity and source-unit attestation identity; raw candidate counts are not
durable entity/form/evidence novelty counts.

Content-tree emission applies stage witnesses and the supplied existing-trunk
bitmap to entity novelty only. Already computed compositional forms survive an
existing root and repeated subtree occurrences. The previous novel placement
winners remain first, followed by remaining raw forms; tier-0 and singleton
scaffolds retain their collapse behavior. The native source/form control emits
four observations of one E from two sources, retains two exact D identities,
and materializes three source-unit associations because one source observed
both forms. Exact repetition of that source/unit/form keeps count one.

Grammar composition and its source-representation owner retain computed
physicalities independently of entity novelty. The drain's presence bitmap and
stage witness receipts still control E insertion; they do not discard already
computed P candidates. Reused AST identities retain their actual spans and
multi-constituent forms. Actual PGN parser controls cover repeated source
drains, existing placement receipts, alternate native-composed geometry and
repeated source-representation compositions without duplicate E rows.

An explicit tier-0 content root or ordered singleton now observes the existing
atomic Content body copied from its verified loaded floor record: unchanged E
and placement ID, exact coordinate/Hilbert, null trajectory, zero constituents,
and null residual/source dimension. It emits no E row. Ordered atom/E/coordinate
claims are checked against the floor before batch mutation. Interior atomic
leaves remain references in their parent's trajectory and produce no extra
root-observation rows. Higher-tier ordered singletons carry only a reference
and coordinate, so they create no arbitrary form; a subsequent operation that
needs their body requests its actual provider or a separately admitted source
body. Native controls prove that missing-body frontier and its resolution.

## Geometry and finite derivation

The identity plan contains ordered structure and a list of every reference
occurrence. It does not manufacture coordinates for missing references. The
realized-E field can use its supplied physicality body. A descriptor view's
carrier references require actual selected child physicalities and an explicit
recipe/epoch receipt. Using verified current Content placements does not prove
the historical child curve of an old observation.

`physicality_descriptor_materialize` accepts the original capture, actual
current Content provider stages, actual admitted placement winners, checked
absence ids and one actual source/source-unit/prior tuple per source body.
It publishes a sorted unique pending frontier with no generated stage until
the finite original-body closure is available. The provider order is declared
by `PhysicalityCurrentFloorAdmittedWinnerRecipeV1`: current database Content,
mapped codepoint floor, then the actual placement winner this writer will
install after a checked database absence. Alternate raw source bodies never
choose the provider by incidental order or by a different minimum-id rule.

Every view contains a canonical sorted receipt of the selected bodies reachable
from that root. A change to C in A→B→C changes A's view receipt even when A and
B retain the same exact bodies. Unrelated batch neighbors cannot change that
receipt. Visited exact body ids terminate source cycles; generated descriptor
rows are never fed back into provider closure. Each ordinary reference selection
retains the real E operand, selected exact D (or pinned floor receipt), carrier
identity and reachable scope. The descriptor D remains immutable content while
the view V identifies this explicit geometry recipe and selection.

The registered `HAS_PHYSICALITY` relation associates E with D using the actual
source and source-unit context. A raw source-unit receipt is not assumed to be
an existing E: the native owner emits a canonical context entity containing
typed source-id and receipt identifiers, each represented by sixteen exact
octets through the ordinary numeric vocabulary. Native batch dedup retains one association per
such tuple and the latest supplied timestamp; repeated internal candidates do
not multiply observation count. The shared writer's existing attestation-id
presence exclusion owns durable replay behavior. Ordinary `fold_replayable`
transport remains enabled; its alternate mode belongs to the atomic consensus
participant path and is not a generic dedup switch.

`physicality_descriptor_generated_source_create` builds the ordinary content
entity for `substrate/source/PhysicalityDescriptorAdmission/v1` through the
actual content owner and returns its declaration stage and content id. The
database operation uses that returned id for generated provenance and returns
the source, vocabulary and generated stages together. A caller's literal hash
is not relabeled as an ordinary source entity.

The normal source-stage set and a requested generated view have different
provenance. Generated views must not automatically become new source
observations to reflect again. This is finite requested derivation, not a
hardcoded reflection-depth ceiling. Further views may be requested explicitly.

## Typed readback

`physicality_descriptor_readback_build` consumes a bulk-hydrated catalog of
ordinary composition nodes and child operands. It verifies each native content
identity, field width, schema and numeric representation, reconstructs the
exact body, and rechecks each root through the same native planner. Missing or
malformed child records fail before output.

The existing GIN expression on Content trajectory constituent ids can select
candidates containing both E and the canonical schema constituent. That hit
requires native typed validation; containment alone does not establish a form.
The resulting descriptor D is an ordinary entity whose Content trajectory can
use the existing typed trajectory reader. Product results must expose D and its
observation/derivation scope. Joining every form onto `structural.entity_curve`
by E alone would multiply occurrences and mix placements, so it is not a valid
all-form read implementation.

## Remaining production work

The accepted work continues through these concrete integration points:

1. Prove every active producer reaches the shared raw-observation boundary,
   including singleton floor observations and cache/ledger reuse. The builder
   retains raw forms separately from selected placements; a supplemental raw
   sidecar cannot omit a selected physicality. Native source ranges identify
   actual emitted rows and explicit producer priors supply their trust policy.
2. Execute the normal writer's new database controls on the host. The writer
   materializes all raw forms before probing the augmented semantic journal,
   imports the returned source/vocabulary/descriptor stages through the native
   tuple owner, and uses ordinary COPY/merge. Generated evidence, its consensus
   fold, source-integrity verification and journal claims share the control
   transaction. Existing E/P COPY transactions retain their established retry
   behavior. A source-only historical receipt suppresses repeated conversation
   append while permitting descriptor backfill; source verification still runs.
3. Capture server-owned projection changes such as `conversation.write_manifest`
   through the same native owner before mutable placement overwrite.
4. Implement the indexed schema-plus-E candidate query, bulk child hydration,
   native typed validation and direct D read surface. Preserve existing typed
   placement compatibility and expose actual retained form ids.
5. Prove normal ingest, replay, alternate forms of an existing E, repeated exact
   bodies, source observations, direct D readback and all-form indexed lookup on
   the actual host. Measure durable output throughput at that same boundary.

The client admission boundary reserves one aggregate payload grant for raw
stages, source metadata, SQL input copies, returned tuples/ids, imported native
stages and decoded evidence. Native import receives the remaining grant for
each stage. The server reports its snapshot, provider rounds, two set queries
per round, expanded Content hashing work, stored vertices, retained tuple bytes
and native reservation peak. The receipt also reports actual generated E/P/A
stage rows before merge. These counts distinguish attempted generated rows,
source rows, committed insertions and replay; none is a games-per-second claim.

## Native verification

`test_physicality_descriptor.cpp` is registered in `laplace_core_tests` and uses
the real Original identity, trajectory, mantissa and IntentStage owners. Its
controlled vocabulary makes local representation tests possible without
claiming an installed Unicode floor. Tests cover exact body reuse, alternate
forms, batch independence, retained ordinary references, factor distinction,
binary64/null fidelity, 65,537 logical members, real COPY capture, typed readback,
malformed vocabulary, malformed records and admitted allocation ceilings.

Plan bytes report retained native allocations. Capture bytes include its owned
plan. Readback reports retained decoded bytes and peak decoder-plus-verifier
bytes separately; the temporary verification plan is released. Limits bound
the combined work, excluding borrowed inputs and allocator bookkeeping. These
receipts are allocation accounting, not process RSS or database throughput.

The current local composite passes 148 native tests, including legacy placement
identity/Content laws, the repaired native COPY fixtures, actual provider
emission, generated source/context entities and direct descriptor readback.
The freshly instrumented address/undefined-behavior sanitizer composite passes
139 tests. Tests load a controlled ASCII floor through the actual native loader;
they do not establish installed full-floor, PostgreSQL or normal-ingest parity.
An executable mutation removing transitive selection scope is detected by the
A→B→C test. Forced centroid allocation failure also preserves canonical output.

The materializer uses a bounded native memory resource, explicit shared centroid
workspace and a bounded stage allocator which includes simultaneous old/new
buffer growth. It reports retained and peak allocation bytes separately. The
vocabulary initializer reserves 64 KiB for the bounded ordinary text work over
its frozen ASCII literals; that receipt is a documented upper-bound reservation,
not a measured scratch peak. Floor id lookup is prepared explicitly under the
floor publication gate, has an indexed allocation receipt and cannot turn an
allocation failure into a false absent entity during materialization.

`physicality_descriptor_stages_preflight` scans actual stored carriers without
expanding runs, validates declared logical counts, and rejects an exhausted
logical-work grant before capture hashing. The logical receipt counts Content
hash operands, while every typed/ordinary stored vertex is counted separately.
Raw-body hashing per materializer invocation is
`source + 2*current + 2*admitted` expanded Content occurrences; the initial
source capture and any stage-add construction have their own passes. Generated
ordinary descriptor operands are structural work separate from raw RLE
expansion. The database bridge must account each pass and its coexisting input,
provider, capture and output allocations instead of reporting one pass per
database request.
